# 정산 대사 근거 실습

가상의 거래 원장(`postings`)과 가맹점 정산 명세(`settlements`)를 거래 ID별로 비교하는 오프라인 Python 실습입니다. 각 ID는 양쪽에 한 번씩 나타나야 하며, 가맹점과 **부호 있는 정수 금액(원)**이 일치해야 합니다.

## 확인하는 항목

- 정산 명세가 없는 거래, 원장에 없는 정산 명세, 가맹점 또는 금액이 다른 거래를 따로 보고합니다.
- 중복 ID, 잘못된 자료형, 0원 금액은 입력 오류로 처리합니다.
- 정렬·정규화한 입력의 SHA-256을 보고서에 넣어 어떤 자료를 검사했는지 다시 확인할 수 있게 합니다.
- 가맹점별 원장 합계·정산 합계·차액을 함께 보고합니다. 합계가 우연히 상쇄돼도 개별 거래의 불일치가 있으면 검토 대상으로 남깁니다.
- 원장에 `reversal_of`가 있으면 음수 환불이 같은 가맹점의 원거래 한 건과 정확히 상쇄되는지 확인합니다. 원거래 누락, 금액 차이, 원거래에 연결된 복수 환불은 건별 검토 대상으로 표시합니다. 기존 세 필드 형식도 그대로 받습니다.

## 실행과 검증

저장소의 `samples/match.json`은 모두 가상 데이터입니다. 저장소에 포함된 표준 라이브러리만 사용합니다.

```powershell
python -B reconcile.py samples/match.json
python -B -m unittest discover -s tests -v
```

종료 코드는 완전 일치 `0`, 검토할 불일치 `1`, 입력 형식 오류 `2`입니다. 이 도구는 돈을 이동시키거나 PAYCO·은행·과거 근무 회사의 시스템에 연결하지 않습니다. 실제 금융 서비스 운영 경력의 증빙이 아니라, 정산 결과를 신뢰하기 전에 어떤 근거를 확인할지 보여 주는 예제입니다.


## 구현 깊이와 검증

원장·정산 ID 인덱스와 역거래 연결을 대조한다. 순액 상쇄로 가려지는 미일치 노출을 absolute 금액 합계로 반환하고 matched 집합을 한 번 생성해 노출 순회를 선형으로 유지한다.

- **시간·공간 복잡도:** 원장 p개·정산 s개: O((p+s) log(p+s)), 노출 합계 O(p+s), 공간 O(p+s).
- **불변조건:** 합계 0이어도 건별 불일치·절대 노출 유지, 역거래의 역거래는 정상 환불이 아니다.
- **경계·기준 검증:** 10,000개 순열 정산과 독립 절대금액 합계, 순액 0/미일치 노출 200, 64비트 경계.
- **실행:** 프로젝트 폴더에서 `python -B -m unittest discover -s tests`.
- **한계:** 기존 계약의 연결 없는 음수 거래는 유지한다. 수수료·부분환불·운영 PG 규칙은 별도 모델이 필요하다.

자료구조·상태 전이·불변조건을 실행 가능한 합성 실습으로 검증한다. 공인 프로그래머스 레벨, 측정하지 않은 성능 배율, 과거 회사 운영 성과를 뜻하지 않는다.
