# 상품 변경 안전 검토 실습

GS리테일 MD AX 담당 공고의 상품 업무 시스템 개발·운영 문제를 가상 데이터로 재현한 오프라인 Python 도구입니다. 상품 가격·할인·재고 변경이 동시에 일어날 때 버전 충돌, 원가 이하 판매, 큰 가격 하락, 잔여 재고가 있는 상품 삭제를 구분합니다. 실제 GS리테일 자료나 서비스에는 접근하지 않았습니다.

## 왜 만들었나

AI 도구가 상품 변경안을 빠르게 제안해도 게시 전에 정형 정책을 적용해야 합니다. 이 실습은 제안의 출처나 문장의 설득력에 기대지 않고 현재 버전과 변경안을 대조합니다. `PASS`는 정적 정책만 통과했다는 뜻이며 실제 게시나 판매 승인에 사용하지 않습니다.

## 실행

Python 3.11 이상에서 외부 패키지 없이 실행합니다.

```powershell
conda run -p C:\Users\ijinz\miniconda3 python -B -m unittest discover -s tests -v
conda run -p C:\Users\ijinz\miniconda3 python -B audit.py samples/safe-change.json
```

입력은 `change_id`, 현재 상품 `current`, 변경 상품 `proposed`, 삭제 목록 `removed`입니다. 금액은 원 단위 정수입니다. 변경 상품의 `version`은 현재 상품 버전과 같아야 하고, 신규 상품은 0이어야 합니다. 삭제는 `expected_version`으로 현재 버전을 지정합니다. 이 도구는 입력 순서가 달라도 같은 자료를 식별하도록 SHA-256을 만듭니다. 이것은 서명이나 승인 기록이 아닙니다.

## 판단과 검증

- `BLOCK`: 버전 불일치, 할인 후 가격이 원가 이하, 잔여 재고가 있는 상품 삭제.
- `REVIEW`: 기존 할인 후 판매가에서 20%를 초과해 하락한 경우. 더 엄격한 차단 조건이 함께 있으면 `BLOCK`을 우선합니다.
- `PASS`: 위 조건에 걸리지 않은 정적 변경. CLI 종료 코드는 차례로 2(입력 오류), 1(검토·차단), 0(통과)입니다.

정상 변경, 버전 충돌, 원가 이하 판매, 큰 가격 하락, 재고 있는 삭제, 중복 SKU·불리언 금액 거부, 입력 순서와 명령행 종료 코드를 테스트합니다. 수요·세금·판매 채널 정책·실시간 재고 경합·법적 가격 표시는 검사하지 않습니다. 사용자가 문제와 품질 조건을 지정했고 공개 코드는 AI 보조로 작성했습니다.

[가상 입력](samples/safe-change.json)과 [검증 코드](tests/test_audit.py)를 함께 확인할 수 있습니다.
