# 가상 이체 기장 완결성 검사 실습

한 계좌의 이벤트만 재생하면 두 계좌 사이에 돈이 옮겨질 때 차변과 대변이 모두 기록됐는지 놓칠 수 있습니다. 이 실습은 **가상의 원화 계좌** 두 개 이상과 이체 명령, 관측된 기장 기록을 분리해 입력받습니다. 이체별로 정확히 두 기장이 있고 금액이 보존되는지 검사한 뒤, 순서대로 잔액을 계산합니다.

## 실행

저장소 루트에서 실행합니다. Python 표준 라이브러리만 사용합니다.

```powershell
python -B ai/transfer-posting-evidence-lab/audit.py ai/transfer-posting-evidence-lab/samples/transfer.json
python -B -m unittest discover -s ai/transfer-posting-evidence-lab/tests -v
```

정상은 종료 코드 `0`, 기장 누락·금액 차이·잔액 부족 등 검토 필요 상태는 `1`, 잘못된 입력과 충돌은 `2`입니다.

## 검사 기준

- 같은 이체 ID와 내용의 재전송은 한 번만 반영합니다. 같은 ID의 다른 내용과 중복·누락된 이체 순서는 입력 오류로 거부합니다.
- 출금 계좌의 음수 기장과 입금 계좌의 양수 기장이 **각각 정확한 금액**으로 있어야 이체를 재생합니다. 한쪽만 기록되거나 다른 계좌·금액으로 기록되면 잔액을 확정하지 않습니다.
- 순서별 잔액 부족과 계좌별 예상 잔액 차이를 따로 보고합니다. 입력 순서·동일 재전송에 관계없이 정규화한 SHA-256을 근거 식별자로 출력합니다.
- 앞선 이체에 기장 누락이나 잔액 부족이 있으면 이후 이체 재생을 중단하고 `REPLAY_BLOCKED`와 최초 차단 이체 ID를 남깁니다. 검증된 앞부분의 추적만 보존하여 확정되지 않은 잔액으로 후속 거래를 계산하지 않습니다.

## 설계 경계

검사는 하나의 JSON 입력에 포함된 가상 기장만 대상으로 합니다. 데이터베이스 트랜잭션의 실제 원자성, 동시 요청 격리, 금융기관의 정산 또는 지급 확정을 증명하지 않습니다. 고객 정보·회사 시스템·외부 API에는 접속하지 않으며, 이 공개 실습은 과거 직장 경력이 아닙니다.


## 구현 깊이와 검증

이체·기장 인덱스와 sequence 재생을 결합한다. 대상 계좌 입금이 64비트 상한을 넘으면 출금도 적용하지 않고 후속 재생을 차단한다.

- **시간·공간 복잡도:** 계좌 a개·이체 t개·기장 p개: O(a+p+t log t), 공간 O(a+p+t).
- **불변조건:** 완전한 차변/대변 한 쌍, 합계 보존, 비음수 64비트 잔액.
- **경계·기준 검증:** 대상 잔액 overflow 시 빈 trace·미확정 잔액, 잘못된 계좌 금액 상한.
- **실행:** 프로젝트 폴더에서 `python -B -m unittest discover -s tests`.
- **한계:** 오프라인 재생이며 실제 DB 동시성·은행 원자성 증명이 아니다.

자료구조·상태 전이·불변조건을 실행 가능한 합성 실습으로 검증한다. 공인 프로그래머스 레벨, 측정하지 않은 성능 배율, 과거 회사 운영 성과를 뜻하지 않는다.
