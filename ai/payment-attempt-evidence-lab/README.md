# 결제 시도·제공자 응답 근거 실습

가상의 결제 요청이 타임아웃된 뒤 같은 멱등 키로 재전송됐을 때, 로컬 응답만으로 결제 성공을 단정하지 않고 제공자의 관측 이벤트와 대조하는 오프라인 Python 도구입니다. 실제 결제망·고객 자료·돈과 연결하지 않습니다.

## 확인하는 문제

- 같은 멱등 키의 재시도는 요청 ID·가맹점·정수 금액이 모두 같아야 합니다. 다른 내용이 섞이면 충돌입니다.
- 시도 번호의 누락, 중복 번호, 제공자 이벤트 ID 중복을 검사합니다.
- 제공자 관측이 없으면 로컬 `ACK`가 있어도 결과를 `UNKNOWN`으로 남깁니다. 타임아웃 이후에도 임의 재청구를 정당화하지 않습니다.
- 제공자 금액 차이·상충된 확정/거절·로컬 거절과 제공자 확정을 검토 대상으로 표시합니다.
- 구독 접근권 판단에 쓸 수 있도록 키별 `entitlement_gate`를 반환합니다. 단일 제공자 확정과 모든 검사 통과가 함께 있어야 `ELIGIBLE`, 정상 거절은 `NOT_ELIGIBLE`, 결과 누락·충돌·금액 차이는 `REVIEW`입니다.
- 확정 뒤 제공자의 취소 관측 `REVERSED`가 한 건 있고 금액과 원확정이 일치하면 접근권 후보를 `NOT_ELIGIBLE`로 바꿉니다. 확정 없는 취소, 중복 취소, 거절과 섞인 취소는 `REVIEW`로 남깁니다.
- 정렬한 가상 입력의 SHA-256을 반환해 어떤 근거를 대조했는지 식별합니다.

## 실행

```powershell
python -B audit.py samples/payment.json
python -B -m unittest discover -s tests -v
```

종료 코드는 통과 `0`, 검토 필요 `1`, 입력 형식 오류 `2`입니다. `PASS`는 이 가상 자료의 내부 정합성만 뜻합니다. 결제 승인, 정산 완료, 원장 반영, 실제 금융 서비스 운영 경험을 증명하지 않습니다.

## 설계 한계

이 실습은 제공자 응답이 신뢰할 수 있는 자료라고 가정한 **정적 대조**입니다. `ELIGIBLE`은 실제 접근권 부여 명령이 아니며, 서명 검증, 네트워크 통신, 영속 트랜잭션, 경쟁 조건, 환불·부분 취소, 운영 중 중복 이벤트 흡수는 구현하지 않았습니다. 이전의 거래 ID별 정산 대사 실습과 달리 결제 **요청 재시도와 제공자 결과의 모호성**을 다룹니다.
