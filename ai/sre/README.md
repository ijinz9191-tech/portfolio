# 장애 재현 실습

서비스 간 장애 전파를 재현하고 운영 절차의 복구 효과를 확인하는 백엔드·SRE 실습 앱입니다. Node.js HTTP API, SQLite, 결과를 재현할 수 있는 시뮬레이션 엔진과 브라우저 화면이 함께 동작합니다.

- **상호작용 연결 구조**: 서비스 8개의 의존 관계, 최초 장애와 영향 경로를 탐색합니다.
- **장애 주입**: 사례 4개와 강도를 선택하고 실행·일시 정지·시간 진행을 제어합니다.
- **실시간 신호**: 서버가 계산한 지연·오류율·처리량 변화를 확인합니다.
- **장애 대응**: 원인에 맞는 운영 절차를 적용하고 복구 과정과 시간 순서를 확인합니다.
- **재현과 사후 분석**: SQLite의 스냅샷을 재생하고 사후 분석 JSON을 내보냅니다.

## 빠른 시작

Node.js **24 이상**이 필요합니다. 외부 npm 의존 패키지 설치 없이 실행합니다.

```sh
node --version
npm test
npm run build
npm start
```

브라우저에서 **http://127.0.0.1:4173**을 엽니다. 서버는 로컬 주소에만 연결되고 기본 기록은 `data/lab.sqlite`에 저장됩니다.

[실습 순서·설계·API·보존 정책](APP.md)을 참고하세요.

AI 보조 도구로 구현한 가상 장애 시뮬레이션입니다. 모든 지표는 모델의 출력이며 실제 고객 요청이나 개인의 과거 운영 성과가 아닙니다.

## 구현 깊이와 검증

시뮬레이션 저장을 SQLite 저장점으로 묶었습니다. 현재 실행 상태·활성 실행 포인터·재생 스냅샷·보존 기간 정리가 중간에 실패하면 함께 되돌아갑니다. 저장점은 외부 명령 트랜잭션 안에서도 사용할 수 있고, 명령 실패 시 메모리 상태도 실행 전 사본으로 복구합니다. 타이머 저장 실패는 진행을 중단하고 이전 상태로 돌아갑니다.

- **복잡도**: 직렬화할 상태의 바이트 수를 `S`, 실행 행 수를 `R`, 이번 보존 정리에서 삭제할 행 수를 `K`, 관련 테이블의 전체 행 수를 `X`라 두면 직렬화는 시간·추가 공간 `O(S)`입니다. 실행 목록 순회와 B-tree 갱신을 포함한 저장 경로는 `O(S + R + (K + 1) log X)`의 상한으로 설명하며, SQLite 파일 I/O·저널·잠금 대기 비용은 별도입니다. 삭제 대상 목록을 포함한 애플리케이션 추가 공간은 `O(S + R)`입니다.
- **불변조건**: 성공한 저장에서는 실행 상태와 같은 틱의 스냅샷이 일치합니다. 실패한 저장에서는 앞서 갱신한 실행 행도 남기지 않습니다. 명령 ID 기록은 외부 명령 트랜잭션에 포함되어 실패한 명령을 성공한 재실행으로 오인하지 않습니다.
- **반례 검증**: [시뮬레이션 테스트](tests/simulation.test.mjs)는 스냅샷 INSERT를 거부하는 SQLite 트리거를 주입해 앞서 쓴 실행 상태·기존 스냅샷·스냅샷 수가 그대로인지 검사합니다. 실패를 해제한 뒤 다음 틱 저장이 정상 작동하는지도 확인합니다. 동일 시드 재현, 재개 시 일시 정지, 명령 충돌, 보존 상한 테스트를 함께 유지합니다.
- **한계**: 이 보장은 로컬 SQLite 트랜잭션 경계의 보장입니다. 분산 합의·스토리지 장치 장애·실제 장애 대응 시간이나 처리량을 증명하지 않습니다. 공개 지연·오류율은 합성 모델 값입니다.
