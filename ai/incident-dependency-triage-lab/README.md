# 장애 의존 관계 진단 실습

가상의 다중 서비스 장애를 검토하는 오프라인 Python 도구입니다. 관측된 실패를 의존성 앞단부터 정렬하고, 실패한 의존 서비스가 없는 실패 서비스를 첫 조사 **후보**로 제시합니다. 이후 서비스에 미칠 수 있는 영향도 표시합니다. 정상인 후속 탐침은 장애로 바꾸지 않고 명시적인 반증으로 남깁니다.

```powershell
conda run -n base python -B -m unittest discover -s tests -v
conda run -n base python -B triage.py samples/incident.json
```

입력은 크기가 제한된 비순환 방향 그래프입니다. 알 수 없는 의존성, 순환, 중복 서비스, 근거 누락, 잘못된 상태 값은 거부합니다. 잠재 영향 범위와 실제 관측된 후속 실패를 따로 보고하므로, 연결돼 있다는 이유만으로 정상 탐침을 실패로 취급하지 않습니다. SHA-256 해시로 정규화한 입력과 결과를 연결합니다. 출력은 조사 계획이며 확정 원인이나 운영 서비스의 자동 재시작 지시가 아닙니다.

새 입력에는 평가 시각 `evaluated_at`과 서비스별 관측 시각 `observed_at`을 함께 기록합니다. 시간대가 없는 값, 미래 관측, 평가 시각보다 5분 넘게 오래된 관측은 진단을 거부합니다. 이전 입력 형식도 읽을 수 있지만 결과에 `LEGACY_UNCHECKED`를 표시해 최신성을 확인했다고 주장하지 않습니다. 가상 입력 파일은 최신성 검사 경로를 보여줍니다.

모든 자료는 가상입니다. 고용주 시스템, 실시간 관측값 또는 비공개 장애 자료를 사용하지 않습니다. 기존 장애 재현 실습의 장애 시뮬레이션·운영 절차 상태 기계와 구분되는 신규 SRE 의존 관계 분석 자료입니다.

## 구현 깊이와 검증

`analyze`는 명시적인 반복자 스택과 방문 중·방문 완료 집합으로 깊은 의존 그래프를 검사합니다. 재귀 DFS의 의존성 우선 순서를 보존하면서 파이썬 재귀 깊이에 의존하지 않습니다. 역방향 인접 목록은 후보에서 영향을 받을 수 있는 서비스만 탐색합니다. V개 서비스·E개 의존 간선에서 그래프 계산은 후보 R개에 대해 시간 O(V+E+R(V+E)), 공간 O(V+E+RV)이며 ID·의존 목록·출력 정렬 비용은 별도입니다. 서비스는 최대 10,000개, 서비스별 의존은 최대 20개입니다.

불변조건은 의존성을 먼저 검토하고, 모든 순환을 거절하며, 도달 가능한 정상 서비스도 실패로 바꾸지 않는 것입니다. `tests/test_depth.py`는 1,500개 서비스의 깊은 체인·순환과 고정 난수 DAG의 전이 폐쇄 기준구현을 대조합니다. 모든 후보의 영향 결과를 반환하므로 후보가 많으면 출력 자체도 커지며, 연결 관계만으로 장애 원인을 확정하지 않습니다.
