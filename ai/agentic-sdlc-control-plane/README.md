# 에이전트 개발 절차 제어 실습

가상 NPU 자산 목록, 자원 배치, 여러 구성 요소의 배포 판단, 승인 범위 안의 자동 조치를 다루는 Node.js 24 제어 실습입니다. 외부 패키지는 필요하지 않습니다. NPU 카드·파이프라인 결과·서비스 신호·장애는 모두 가상이며 실제 NPU·베어메탈·Slurm·OpenStack·Rebellions 운영 경험을 주장하지 않습니다.

## 실행

```bash
npm test
npm run simulate
```

## 해결하려는 문제

드라이버·펌웨어·집합 통신 구성 요소는 함께 빌드하고 시험해야 하며, 희소한 가속기 자원은 안전하게 예약해야 합니다. AI 보조 장애 절차에서 자산 상태를 바꾸려면 엄격한 도구 경계, 최신 근거와 명시적 승인이 필요합니다.

## 주요 기능

- NPU 노드와 전체에서 고유한 카드 목록을 검증합니다.
- 메모리·기능·펌웨어·최대 노드 수 조건으로 정상 카드를 예약합니다.
- 오래된 임대, 성능이 저하된 용량, 중복 할당을 거부합니다.
- 드라이버·펌웨어·통신 라이브러리 배포에 빌드·단위·통합·하드웨어 시뮬레이션·보안 근거를 요구합니다.
- 구성 요소별 결과를 후보 소스 버전과 현재 자산 임대에 연결합니다.
- SLO 오류 예산과 p95 지연 조건을 적용합니다.
- 도구 허용 목록이 명시된, 범위가 제한되고 재현 가능한 에이전트 계획을 만듭니다.
- 격리·롤백 조치에는 계획에 연결된 승인 해시를 요구합니다.
- 도구 결과를 변조 감지 근거 원장에 저장합니다.

## 검증 범위

자산 목록 손상, 용량 제약, 저하된 카드, 펌웨어 불일치, 중복 임대, 배포 단계 실패, 오래된 소스·임대 근거, SLO 위반, 승인 강제, 오래된 사실, 도구 허용 목록과 감사 변조를 테스트합니다.

[설계 설명](docs/architecture.md), [실행 절차](docs/runbook.md), [검증 기준](docs/verification.md)을 참고하세요.

## 기여 및 사용 범위

지원자는 경력 목표·원본 사실·검토 판단을 제공했습니다. AI 보조 도구로 코드와 문서를 구현·테스트했습니다. 이 자료는 공개 포트폴리오 근거이며 과거 재직 업무나 운영 성과와 구분합니다.

## 구현 깊이와 검증

첫 번째 정상 카드의 펌웨어에 배치가 묶이던 선택을 바꿨습니다. 펌웨어별로 각 노드의 적격 카드 수를 계산하고, 용량이 큰 상위 `maxNodes`의 합으로 그 펌웨어의 배치 가능성을 판단합니다. 가능한 펌웨어가 있으면 필요한 수만 예약한 새 자산 목록을 반환하며 원본 목록은 변경하지 않습니다.

- **복잡도**: 카드 수를 `C`, 노드 수를 `N`, 적격 펌웨어 종류 수를 `V`, 요청 기능 수를 `F`, 카드당 최대 기능 수를 `L`, 직렬화할 자산·요청 크기를 `B`라 두면 `O(C F L + V(C + N log(N + 1)) + V log(V + 1) + B)` 시간입니다. 기능 검사는 배열의 `includes`, 자산 지문은 직렬화·해시를 사용하므로 이 비용을 함께 포함합니다. 예약 결과 사본·후보 목록·해시 입력을 포함한 추가 공간은 `O(C + N + V + B)`입니다. 펌웨어 혼합을 허용하면 검색 후보는 하나입니다.
- **불변조건**: 카드 ID는 전체에서 고유하고, 건강·유휴·메모리·요청 기능 조건을 충족한 카드만 선택합니다. 동일 펌웨어 모드에서는 선택 카드의 펌웨어가 같으며 노드 수 상한·요청 카드 수를 지킵니다. 실패한 예약도 원본 자산이나 기존 임대를 바꾸지 않습니다.
- **완전 탐색 기준 대조**: [자산 테스트](tests/inventory.test.js)는 첫 카드의 오래된 펌웨어로는 부족하지만 다른 펌웨어로는 가능한 반례를 재현합니다. 시드가 고정된 120개 소규모 사례에서 4개 노드의 모든 부분집합과 3개 펌웨어를 열거한 기준 구현과 배치 가능 여부를 비교합니다. 잘못된 노드 상한·무한대 메모리·잘못된 기능 목록도 거부합니다.
- **한계**: 상위 노드 용량 합은 이 모델의 동일 펌웨어·카드 개수·최대 노드 수 제약에 대한 정확한 가능성 검사입니다. 통신 거리·토폴로지·대기 시간·실제 NPU 성능 최적화까지 증명하지 않습니다. 에이전트 조치는 허용 도구·승인 근거를 적용한 합성 실행이며 운영 자산에 연결하지 않습니다.
