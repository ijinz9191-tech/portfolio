# 계좌 이벤트 순서·멱등 재생 실습

서버가 동일한 이벤트를 다시 받거나 순서가 뒤바뀐 경우, 단순 합계만으로는 계좌 상태를 설명하기 어렵습니다. 이 오프라인 실습은 **가상 계좌**의 버전별 증감 이벤트를 정렬해 재생하고, 이벤트 ID의 동일한 재전송과 내용 충돌을 구별합니다.

## 실행

저장소 루트에서 다음 명령을 실행합니다. Python 표준 라이브러리만 필요하며 Conda Python에서도 같습니다.

```powershell
python -B ai/account-event-replay-lab/replay.py ai/account-event-replay-lab/samples/account.json
python -B -m unittest discover -s ai/account-event-replay-lab/tests -v
```

정상 검사는 종료 코드 `0`, 검토할 잔액·버전 문제는 `1`, 잘못된 명세와 충돌은 `2`를 돌려줍니다.

## 판단과 근거

- 동일 ID와 내용의 재전송은 한 번만 반영하고 횟수를 표시합니다. 같은 ID의 내용이 다르거나 서로 다른 ID가 같은 버전을 차지하면 입력을 거부합니다.
- 버전 누락이나 재생 중 음수 잔액이 발견되면 계산된 잔액을 공개하지 않습니다. 최종 잔액은 별도 예상값과 대조합니다.
- 입력 순서와 동일 재전송 횟수에 영향을 받지 않는 정규화 SHA-256, 버전별 잔액 추적과 이슈를 출력합니다.
- 선택적인 `checkpoints`에 중간 버전과 기대 잔액을 적으면 재생 중간의 스냅샷 불일치를 별도로 찾아냅니다. 불일치가 있으면 최종 잔액을 공개하지 않습니다. 기존 네 필드 입력은 계속 동작합니다.

## 범위

예시의 계좌와 금액은 모두 가상입니다. 실제 증권 계좌, 거래 주문, 금융기관 API, 고객 자료에 접근하지 않습니다. 출금 가능 잔액·결제 확정·정산 적합성 같은 실서비스 정책을 검증하는 도구가 아닙니다. 공개 코드는 AI 보조로 만든 지원용 실습이며 과거 실무 경험으로 제시하지 않습니다.


## 구현 깊이와 검증

버전/ID 인덱스로 재전송을 제거하고 순차 잔액 재생을 한다. 입력과 중간 잔액을 부호 있는 64비트 범위에 제한한다. 연속 버전 검사는 range 목록을 추가 생성하지 않는 enumerate 대조를 사용한다.

- **시간·공간 복잡도:** n개 입력, u개 고유 이벤트: 인덱스 O(n), 정렬 O(u log u), 재생 O(u), 공간 O(n+u).
- **불변조건:** 잔액 0~2^63-1, 동일 ID 내용 동일, 연속 버전, 실제 잔액과 체크포인트 일치.
- **경계·기준 검증:** 20,000개 역순 이벤트와 100개 재전송을 독립 누적 기준과 비교하고 overflow 시 trace·잔액을 검사한다.
- **실행:** 프로젝트 폴더에서 `python -B -m unittest discover -s tests`.
- **한계:** 영속 저장·동시 writer·실제 금융 처리는 포함하지 않는다.

자료구조·상태 전이·불변조건을 실행 가능한 합성 실습으로 검증한다. 공인 프로그래머스 레벨, 측정하지 않은 성능 배율, 과거 회사 운영 성과를 뜻하지 않는다.
