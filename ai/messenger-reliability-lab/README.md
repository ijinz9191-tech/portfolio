# 메신저 신뢰성 실습

기업용 메신저의 메시지 전달 경계를 다루는 가상 Node.js 24 실습입니다. 중복·순서가 어긋난 명령을 거부하고 대화별 처리량을 제한합니다. 확인 응답 누락을 재시도하고, 횟수가 소진되면 실패 메시지 상태로 옮기며, 재시작 스냅샷 전후에 추가 전용 감사 기록을 보존합니다.

가상 메시지만 사용하며 실제 메신저·클라우드·모바일 클라이언트·회사 시스템 운영 경험을 주장하지 않습니다.

## 실행

```bash
npm test
npm run simulate
npm start
```

HTTP 서버의 기본 주소는 `127.0.0.1:3000`입니다.

## 주요 기능

- 멱등 키 재실행과 내용 충돌 거부
- 대화별 단조 증가 메시지 순서 검사
- UTF-8 내용과 진행 중 전달 수 제한
- `QUEUED → IN_FLIGHT → DELIVERED | DEAD_LETTER` 상태 모델
- 확인 응답 시간 초과와 횟수 제한 지수 재시도
- 순서가 단조 증가하는 추가 전용 감사 이벤트
- 메시지·멱등성·순서 상태의 스냅샷 복원
- 외부 패키지가 필요 없는 로컬 HTTP 연결기와 유형별 실패

## 구현 깊이와 검증

재시도 시각을 메시지 위치 인덱스가 있는 최소 힙으로 관리하고, 대화별 활성 메시지 수를 별도 맵에 유지합니다. 전체 메시지를 훑어 재시도·용량을 계산하는 대신 기한이 지난 항목만 꺼냅니다. 재예약·확인·실패 종료 시 힙을 직접 갱신해 오래된 예약이 누적되지 않도록 했으며, 스냅샷 복원 시 파생 인덱스를 재구축합니다.

- **복잡도**: 활성 메시지 수를 `A`, 이번 틱에 기한이 지난 수를 `K`, 전체 메시지 수를 `M`, 감사 이벤트 수를 `E`라 두면 예약·취소는 `O(log(A + 1))`입니다. 틱은 `O(K log(A + 1) + K log(K + 1))`이며 두 번째 항은 기존 API의 삽입 순서 응답을 유지하는 정렬입니다. 기한이 지난 항목이 없으면 `O(1)`입니다. 힙·위치 인덱스는 `O(A)`, 원장 전체는 메시지 내용 크기를 포함해 `O(M + E + P)` 공간을 사용합니다. 복원은 힙 재삽입으로 `O(M log(A + 1) + E + P)`이며 `P`는 전체 메시지 내용 크기입니다.
- **불변조건**: 활성 메시지마다 예약이 하나이고 종료된 메시지는 예약·활성 수에서 제외됩니다. 대화별 순서·멱등 키·감사 이벤트 순서를 복원 전후에 유지합니다. 시간 초과 계산이 안전 정수 범위를 넘으면 예약을 되돌려 다음 유효 틱이 처리할 수 있게 합니다.
- **기준 구현 대조**: [원장 테스트](tests/ledger.test.js)는 2,000개 메시지의 여러 재시도 시각과 일부 확인 응답을 독립적인 전체 스캔 모델과 비교합니다. 복원 뒤 순서·용량 인덱스, 대기 중 복원, 잘못된 시간 경계에서 상태 보존, 중복 메시지 ID·끊어진 멱등 참조 거부도 확인합니다.
- **한계**: 합성 로컬 원장과 HTTP 실습입니다. 스캔 대조는 결과 동등성 검증이며 실행 시간 개선 비율을 측정한 벤치마크가 아닙니다. 실제 브로커·영속 저장·분산 전달에서 정확히 한 번 전달됨을 보장하지 않습니다.
