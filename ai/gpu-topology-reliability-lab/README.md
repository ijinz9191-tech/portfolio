# GPU 연결 구조와 배치 신뢰성 실습

의존 패키지 없이 Node.js 24로 실행하는 가상 GPU 클러스터 실습입니다. 하드웨어 연결 관계를 고려한 배치, 근거 기반 성능 진단, 승인된 조치만 완료하는 절차를 모델링합니다. 하드웨어·지표·장애 자료는 모두 가상이며 실제 GPU·NPU·RDMA·데이터센터 또는 고용주 운영 경험을 주장하지 않습니다.

## 실행

```bash
npm test
npm run simulate
```

## 주요 기능

- 노드, GPU, NUMA, PCIe 루트, NIC의 연결 구조를 검증합니다.
- 메모리·네트워크·동일 NUMA 조건에 따라 GPU 작업을 배치합니다.
- 불가능하거나 안전하지 않은 배치를 상태 변경 전에 거부합니다.
- 원격 NUMA 접근, PCIe 압박, NIC·RDMA 포화, CPU 데이터 공급 병목, GPU 상태 신호를 진단합니다.
- 허용 목록에 있는 계획, 독립 승인 해시, 변경 후 확인이 있어야 조치를 완료합니다.
- 해시로 이어진 감사 원장과 무결성 검사 스냅샷을 보존합니다.

## 검증 범위

테스트는 정상 배치, 용량 제약, 연결 구조 손상, 중복 할당, 점검 모드, NUMA·PCIe·RDMA 진단, 승인·오래된 계획, 감사 원장과 스냅샷 변조를 다룹니다. 자세한 내용은 [검증 기록](docs/verification.md)과 [실행 절차](docs/runbook.md)를 참고하세요.

## 기여 및 사용 범위

지원자는 경력 목표·사실·검토 판단을 제공했습니다. AI 보조 도구로 코드와 문서를 구현하고 테스트했습니다. 이 채용 준비 프로젝트는 공개 포트폴리오 근거이며 과거 재직 업무나 운영 성과와 구분합니다.

## 구현 깊이와 검증

같은 NUMA 안에서 PCIe 루트의 GPU 수를 집계한 뒤 용량이 큰 루트부터 선택합니다. 입력에서 먼저 나타난 루트에 편향되지 않도록 루트·GPU ID로 동률 순서를 고정했고, 가능한 NUMA 후보를 비교한 뒤 실제 할당을 적용합니다. 요청의 메모리·네트워크 값은 유한한 음이 아닌 수여야 합니다.

- **복잡도**: 노드 수를 `N`, 전체 GPU 수를 `G`, NUMA 후보 그룹 수를 `H`, 노드당 최대 NIC 수를 `I`, 후보에 포함된 최대 NUMA 수를 `U`라 두면 배치 후보 생성·정렬은 `O(N + G log(G + 1) + H I U + H log(H + 1))` 시간, `O(G + H + I)` 추가 공간입니다. 기본 동일 NUMA 모드에서는 `U = 1`입니다. NIC와 후보 NUMA 연결 비교를 포함한 상한이며 전체 부분집합을 실제 배치 경로에서 열거하지 않습니다.
- **불변조건**: 점검 중 노드·비정상 GPU·이미 할당된 GPU는 후보에 포함하지 않습니다. 선택된 GPU 수·메모리·네트워크·동일 NUMA 제약을 충족한 경우에만 할당하고 같은 작업의 중복 할당을 거부합니다. 동일 NUMA의 같은 NIC 조건에서는 용량 내림차순 선택이 필요한 PCIe 루트 수를 최소화합니다.
- **완전 탐색 기준 대조**: [배치 테스트](tests/lab.test.js)는 시드가 고정된 100개 가상 사례마다 GPU 8개의 모든 부분집합을 열거해 같은 NUMA에서 가능한 최소 PCIe 루트 수와 결과를 비교합니다. GPU 입력 순서를 뒤집어도 결과가 같고, 무한대 메모리·네트워크 요청을 거부하는지도 확인합니다.
- **한계**: 부분집합 대조의 최적성 범위는 동일 NUMA에서의 PCIe 루트 수입니다. 여러 NUMA를 허용한 모든 배치의 네트워크 최적성이나 클러스터 전체 장기 스케줄 최적성을 주장하지 않습니다. 합산 NIC 용량과 점수는 합성 모델이며 실제 RDMA 처리량·GPU 성능을 측정한 값이 아닙니다.
