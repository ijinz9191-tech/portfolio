# 구독 접근권·제휴사 확인 대조 실습

합성 결제 근거, 구독 접근권 상태, 제휴사 확인 응답을 같은 구독 ID와 청구월로 묶어 비교하는 오프라인 Python 도구입니다. 결제가 확정됐다는 기록 하나만으로 실제 접근권이나 제휴사 반영까지 완료됐다고 가정하지 않습니다.

## 검사 범위

- 청구월별 결제 1건과 고유 결제 ID를 확인하고, 중복·누락·잘못된 금액을 거절합니다.
- 확정 결제에는 활성 접근권과 성공 제휴 응답이 각각 한 건씩 있어야 `ELIGIBLE`입니다. 결제 거절 후 활성 접근권, 응답 누락, 다른 결제 ID 참조, 다른 청구월, 중복 기록은 `REVIEW`입니다.
- 정상 거절과 접근권 없음은 `NOT_ELIGIBLE`로 남깁니다. `ELIGIBLE`은 운영 서비스에 실제 접근권을 부여하라는 명령이 아닙니다.
- 입력 목록의 순서와 무관한 SHA-256을 남겨 판단에 사용한 합성 근거를 식별합니다.

## 재현

```powershell
python -B reconcile.py samples/confirmed.json
python -B -m unittest discover -s tests -v
```

종료 코드는 정합성 통과 `0`, 검토 필요 `1`, 입력 오류 `2`입니다. 표준 라이브러리만 사용합니다.

## 설계 경계

결제 결과의 진위·서명, 제휴사 네트워크 통신, 실제 구독 계정과 기간 만료, 환불·부분 취소, 경쟁 조건, 영속 데이터베이스 트랜잭션은 다루지 않습니다. 모든 ID와 금액은 가상 자료입니다. 케이티 밀리의서재나 다른 고용주의 실제 결제·제휴 시스템 경험 또는 운영 안전성을 주장하지 않습니다. 기존 [결제 시도 근거 실습](../payment-attempt-evidence-lab/README.md)은 재시도와 제공자 응답의 모호성을 다루며, 이 도구는 확정 이후 접근권과 제휴 확인의 대조를 다룹니다.


## 구현 깊이와 검증

구독/기간 그룹과 전역 payment_id 소유자 인덱스를 함께 사용한다. 다른 구독/기간의 결제 ID를 권한·제휴 확인이 재사용하면 별도 상충으로 보고한다. 달력 연도 0000과 유니코드 숫자 기간을 거부한다.

- **시간·공간 복잡도:** 총 기록 n개: 인덱스·대조 O(n), 정규화 O(n log n), 공간 O(n).
- **불변조건:** 한 결제 ID는 한 구독/기간의 근거이며 결제·ACTIVE·CONFIRMED가 모두 일치해야 접근 후보.
- **경계·기준 검증:** 교차 구독 결제 참조, 잘못된 연도·유니코드 기간 검증.
- **실행:** 프로젝트 폴더에서 `python -B -m unittest discover -s tests`.
- **한계:** 실제 구독 갱신·부분 기간·파트너 통신은 포함하지 않는다.

자료구조·상태 전이·불변조건을 실행 가능한 합성 실습으로 검증한다. 공인 프로그래머스 레벨, 측정하지 않은 성능 배율, 과거 회사 운영 성과를 뜻하지 않는다.
