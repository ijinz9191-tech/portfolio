# PG 인증 귀환·서버 확인 대조 실습

결제 화면에서 돌아온 성공 신호와 결제 제공자의 서버 확인을 서로 다른 증거로 다룹니다. 브라우저 결과만으로 결제 승인을 확정하지 않고 세션·주문·가맹점·금액·일회성 값의 일치를 검사합니다.

## 실행

```powershell
python -B audit.py samples/authorized.json
python -B -m unittest discover -s tests -v
```

입력은 `sessions`, `returns`, `confirmations`의 세 목록입니다. 각 세션의 `nonce_sha256`은 귀환 값의 SHA-256이며 가상 예제의 값만 포함합니다. 세션·주문 ID, 귀환 ID, 거래 ID의 중복을 거부합니다.

## 판단

- 한 번의 정상 귀환과 한 번의 서버 승인, 주문·가맹점·금액·nonce 일치가 확인되면 `AUTHORIZATION_CANDIDATE`입니다.
- 두 경로가 모두 거절이면 `REJECTED`입니다.
- 한쪽 증거 누락, 중복 귀환·확인, 서로 다른 결과나 식별 값은 `REVIEW`입니다. 확인되지 않은 거래를 성공으로 바꾸지 않습니다.
- 종료 코드는 정상 대조 `0`, 검토 필요 `1`, 입력 형식 오류 `2`입니다. 결과에 입력 SHA-256을 포함합니다.

## 범위와 한계

가상 JSON만 읽는 오프라인 검사기입니다. 서명·인증서 검증, 제공자 API 호출, 영속적 중복 방지, 실제 결제 승인·취소·정산을 수행하지 않습니다. 기존 결제 시도 도구는 **재시도와 제공자 결과**, 이 도구는 **사용자 브라우저 귀환과 서버 확인의 신뢰 경계**를 다룹니다. 둘을 합쳐 실제 운영 PG 경험으로 표시하지 않습니다.


## 구현 깊이와 검증

세션 전체에서 nonce 해시 재사용을 거부해 다른 주문으로 귀환 근거가 재생되는 경로를 막는다. 세 목록을 고유 ID 순으로 정규화해 순열에도 동일 근거 해시를 반환한다.

- **시간·공간 복잡도:** 총 기록 n개: 인덱스 O(n), 정규화 O(n log n), 공간 O(n).
- **불변조건:** nonce는 세션 간 유일, 주문·가맹점·금액은 서버 근거와 동일.
- **경계·기준 검증:** nonce 재사용 거부와 입력 순열 동일 해시.
- **실행:** 프로젝트 폴더에서 `python -B -m unittest discover -s tests`.
- **한계:** 해시는 입력 동일성 근거이며 운영 nonce 만료·서명 검증이 아니다.

자료구조·상태 전이·불변조건을 실행 가능한 합성 실습으로 검증한다. 공인 프로그래머스 레벨, 측정하지 않은 성능 배율, 과거 회사 운영 성과를 뜻하지 않는다.
