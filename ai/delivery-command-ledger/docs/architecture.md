# 설계

`Service`는 하나의 동기화된 트랜잭션 경계 안에서 명령 검증, 상태 전이, 낙관적 버전, 배송 인원별 수용량과 이벤트 추가를 처리합니다. 명령 결과는 입력 내용 지문과 함께 저장합니다. 같은 명령의 재시도는 기존 결과를 반환하고 동일 ID에 다른 내용을 쓰면 `409 Conflict`로 차단합니다.

스냅샷은 배송, 주문 소유 관계, 명령 결과, 이벤트 순서를 한 파일에 기록합니다. 임시 파일을 완성한 뒤 원자적 교체를 시도하므로 미완성 파일이 정상 스냅샷을 덮지 않습니다. `Api`는 로컬 HTTP만 사용하며 상태 확인, 배송·이벤트 조회, 생성·배정·상태 변경 명령을 제공합니다.

운영용으로 확장한다면 메모리 경계는 RDBMS 트랜잭션과 고유 제약으로, 스냅샷은 지속 저장소와 시점 복구로, 로컬 이벤트 목록은 트랜잭션 발신함과 메시지 소비자로 교체할 수 있습니다.
